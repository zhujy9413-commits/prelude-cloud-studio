# 序幕立项调研

更新日期：2026-10-26。用途：判断一句话生成短镜头的平台是否值得继续验证，以及采用云 API 还是自建推理。当前结论是优先验证创作结果和预期的一致性，保留云 API 路线；还没有证据支持购买 GPU 或扩大投放。外部方案资料沿用 10 月 25 日的核验记录，本次更新补充项目实测与试用反馈。

## 问题与需求证据

已确认的发起人需求是电脑网页、一句话生成几秒到十几秒的动态单镜头，界面要有电影感，云海自然翻卷，操作容易理解。生成后的片段应能播放、下载、复用和管理。主要障碍包括不知道如何写镜头、等待过程缺乏反馈，以及示例展示与实际生成存在落差。

2026-10-25 的雨夜案例提供了具体证据：原实现只提交文字，示例静帧没有进入生成请求，实际成片的景别和色彩偏离展示图。10 月 26 日已完成内置雨夜 8 秒和自传月光海岸 5 秒的真实首帧实测，构图与基调得到保留，播放下载通过。这能支持输入链路已修正，不能据此判断所有模型的能力或市场普遍需求。

用户转述一位偏新手朋友操作顺畅、成片较为接近预期；另反馈“继续调整”入口可以找到。未记录重试次数、实际采用、付费或独立二次生成。这是早期定性反馈，不计算成功率或留存。用户明确担心模块过多，因此当前沿用同一创作区，动作引导按需打开，成片回到原输入区继续调整。

## 候选用户与待验证场景

- 内容创作者：为短内容生成一个氛围镜头，关心可用率、下载和重复尝试成本。
- 设计与视觉创作者：把脑中的构图或参考画面变成动态小样，关心主体、光线和镜头运动。
- 初次使用 AI 视频的人：希望少设置即可看到结果，关心示例能否兑现、按钮是否可辨认。

这些是候选细分人群，尚未完成系统外部访谈、用户规模统计或付费验证；已有一位偏新手用户的转述反馈。继续观察真实创作任务，再决定聚焦哪一群体。

## 替代方案与产品启发

| 方案 | 核实的能力或特点 | 对序幕的启发与限制 |
| --- | --- | --- |
| Runway | 官方产品页提供网页创作及图像、视频、音频和编辑模型入口 | 网页创作形式已存在；单靠漂亮首页不足以构成长期差异。没有做同条件成片实测，不作质量排名 |
| 百炼模型 API | 可异步提交文生、首帧图生视频任务，按模型及参数计价 | 序幕补足输入、等待、存储和作品管理；API 接通本身不能证明用户愿意付费 |
| 自建开源模型 | 获得推理与部署控制，需承担硬件、调优和运维 | 适合后续有稳定用量及质量评估之后比较，目前先避免固定投入 |

来源：[Runway 产品页](https://runway.com/product)、[百炼文生视频接口](https://help.aliyun.com/zh/model-studio/legacy-wan-text-to-video-api-reference)、[首帧图生视频接口](https://help.aliyun.com/zh/model-studio/legacy-image-to-video-api-reference/)。核验于 2026-10-25，官网功能说明不等于实测结果。

这些是模型与推理工程，不能直接等同于包含登录、支付、管理和运维的完整 SaaS 平台。仓库显存条件也不代表本机已满足，当前未运行上述开源模型或比较其吞吐。

## 方案判断与成本

保留百炼，是因为已经完成真实文生视频闭环，下一步最需要减少的是成片是否可用的不确定性。自建路线应在同一评估集上比较质量、端到端耗时和每条可用成片成本后再决定。

商业上应关注“每条可用成片成本＝生成总成本÷被接受的成片数”。重复尝试、存储、带宽、审核和运营均会增加成本，不能只看单次模型价格。当前没有留存、转化、收入或获客成本数据，不计算市场规模和盈利预测。

## 下一轮研究

邀请有实际镜头需求的创作者完成自己的任务，记录原目标、输入、模式、等待、修改次数、下载及未采用原因。先用雨夜、云海、月面三类场景比较文字与首帧模式，分别检查构图、主体、光影、运动、稳定性；统计样本数和失败样本，不用最好的一条代表整体能力。

若成片稳定但用户不使用，回到场景与替代方案；若首帧也不能满足预期，调整展示承诺或模型；若质量足够而用量稳定，再比较自建和 API 的完整成本。
