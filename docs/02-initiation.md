# 序幕项目立项报告

版本：2026-10-25 本地验证版。建议有条件继续：围绕电脑端短镜头生成完成质量验证和小范围真实使用，暂不承诺公网商业运营。当前已形成可运行产品，核心价值与商业价值仍需验证。

## 项目定位与立项依据

序幕让用户通过一句中文描述，或选定一张内置参考画面，生成 2–15 秒单镜头视频。用户获得的是能够继续创作的片段，平台承担输入引导、任务等待、结果保存和复用管理。

发起人已持续验证视觉与交互，提出固定导航、柔和字体、真实云海、过渡、等待反馈、作品管理和点击辨识等要求。真实文生视频已跑通；雨夜成片偏离参考画面的反馈，也暴露了预期与输入条件不一致的问题。证据支持继续改进当前闭环，还不足以证明市场需求规模或商业回报。

## 为什么采用 AI 与云 API

用户希望创造未拍摄过的动态镜头，规则动画和素材拼接难以覆盖自由描述。生成模型负责合成画面；规则负责参数校验、时长建议、预算和状态；用户判断创作结果是否可用。

当前百炼 API 已接通，因此先以较低固定投入验证输出价值。自建推理、训练模型或多供应商路由都不是本阶段必要前提。模型更新可能改善画质，也可能削弱单纯调用封装的差异，产品应积累可验证的工作流与质量体验。

## 本阶段目标和边界

本阶段完成自由文字或内置首帧输入、真实生成、可靠等待、播放下载、历史复用和可恢复的作品管理。当前仅在本机运行，支持 720P；首帧模式限定内置云海、雨夜和月面三张 16:9 图片。

不纳入本阶段的有长片剪辑、多镜头时间线、角色训练、用户任意图片上传、公开社区、注册支付和跨设备同步。已有收藏与作品详情属于保留的辅助体验，不再以功能数量扩充本次验证目标。

## 继续投入的依据与门槛

| 判断 | 当前依据 | 下一步门槛 |
| --- | --- | --- |
| 技术闭环可用 | 已有真实文生视频与本地播放下载；接口和状态测试通过 | 首帧模式真实请求、结果及播放下载完成验收 |
| 创作价值可用 | 雨夜反馈表明参考一致性影响接受度 | 用户用自己的任务判断能否采用，记录修改与放弃原因 |
| 成本可控 | 服务端按标价限制每日预算与并发 | 统计每条可用成片的总生成成本，形成可接受成本范围 |
| 体验可理解 | 已实现明显控件、真实状态、等待和转场 | 首次使用者能分清文生、首帧及静帧预览，并独立取得结果 |

当前没有可靠的质量接受率、生成耗时分布、付费意愿基线。先取数，再制定量化放大门槛；不以测试通过代替用户价值通过。

## 投入与经济约束

本阶段主要投入是现有代码维护、真实评估样本、使用观察及文档。尚未确定团队编制、人天、总预算或商业上线日期，不作排期和资源承诺。

当前服务默认按公开标价预留每日 30 元、全局同时一个任务。这是本地保护参数，不是账户余额或实际账单。重试次数与可用率会影响总成本；账号免费额度、优惠及当前余额须在控制台另查。价格与计算见技术说明。

## 风险与决策条件

参考图不能保证后续每帧完全一致。若真实首帧结果仍持续偏离目标，先收紧场景和展示承诺，再评估提示词或替代模型；不继续用静帧暗示可直接复现的成片。

提交结果不明时停止重复提交，核对原任务，避免重复计费。无账号的本机会话无法跨设备找回，不适合直接开放给公众。公网试用前必须补齐正式身份、任务队列、存储、计费约束及运维方案。

若目标用户不愿把结果用于真实任务，缩小或更换场景；若可用成片成本超出用户可接受范围，调整定位和模型；若核心质量始终不足，暂停扩大功能投入。下一阶段是否商业上线，由质量、真实使用和成本证据共同决定。

## 当前待决事项

下一轮先确定并验收首帧真实评估样本，再招募目标创作者。商业用户群、收费方式、可接受等待、正式预算和上线时间均待验证或由项目发起人决定。此报告归档现状与建议，不代表已经批准上述资源投入。
